# دستیار باربرگ شهری — نسخه ۲.۳.۰

این نسخه صفحه شروع را به داشبورد مدیریت ناوگان تغییر می‌دهد. اطلاعات ناوگان در این نسخه به‌صورت محلی روی دستگاه نگهداری می‌شود.

## پیش‌نیازها
- JDK 17
- Android SDK Platform 35
- Android Gradle Plugin 8.7.3
- Gradle 8.9

## ساخت
GitHub Actions به‌صورت خودکار lint، تست واحد و `assembleDebug` را اجرا می‌کند و در صورت موفقیت APK را به‌عنوان Artifact با نگهداری ۳۰ روز منتشر می‌کند.

در محیط دارای Gradle 8.9:
```bash
gradle clean :app:lintDebug :app:testDebugUnitTest :app:assembleDebug
```

خروجی:
`app/build/outputs/apk/debug/app-debug.apk`

## وضعیت فعلی
- صفحه شروع: داشبورد
- مدیریت ناوگان‌ها با SharedPreferences و بازیابی پس از بستن برنامه
- افزودن و حذف ناوگان و جلوگیری از نام خالی/تکراری/بیش از ۶۰ نویسه
- نسخه برنامه: 2.3.0
- کد اولیه تولید و تأیید OTP در `UtcmsApi` وجود دارد، اما اتصال تولیدی تأیید نشده است.

## قراردادهای UTCMS ثبت‌شده

ساختارهای پاسخ استخراج‌شده از صفحات مستندات در `UtcmsContracts.kt` پیاده‌سازی شده‌اند؛ شامل `KeyValueCnt`، `ProvinceCityCnt`، `RegisterInfoCnt`، `ResponseBOLCnt` و فیلدهای `SystemOptionCnt`. جزئیات پوشش و موارد مسدودکننده در `docs/UTCMS-CONTRACT-STATUS.md` آمده است.

## محدودیت مهم اتصال SIPAAD / UTCMS
کد OTP در `UtcmsApi` فعلاً به‌صورت fail-closed غیرفعال است و هیچ درخواست تولیدی ارسال نمی‌کند؛ فعال‌سازی آن منوط به تأیید قرارداد رسمی است. آدرس `.asmx` به‌تنهایی ثابت نمی‌کند سرویس JSON می‌پذیرد یا قرارداد SOAP دارد. پیش از فعال‌سازی باید WSDL یا مستندات رسمی و مجاز، نام دقیق متدها، پارامترها، نوع داده‌ها، الگوریتم هش، روش احراز هویت و نمونه پاسخ از مرجع سامانه دریافت و تطبیق داده شود. ثبت باربرگ و استعلام/تأیید نتیجه نهایی هنوز در این نسخه پیاده‌سازی نشده است.

## امنیت
- رمز یا کلید محرمانه را در مخزن Git قرار ندهید.
- رمز عبور در انتهای تلاش درخواست از `CharArray` پاک می‌شود؛ برای هر درخواست باید حساب/رمز تازه ساخته شود.
- الگوریتم هش موجود تا تأیید رسمی نباید برای تولید استفاده شود.
- TLS pinning فقط پس از دریافت fingerprint معتبر و سازوکار چرخش گواهی قابل تنظیم است.
- استفاده عملیاتی فقط با مجوز رسمی، مشخصات فنی معتبر و آزمون در محیط مجاز انجام شود.

## Gradle Wrapper
فایل `gradle-wrapper.properties` تنظیم شده است، اما فایل باینری استاندارد `gradle-wrapper.jar` و اسکریپت‌های تولیدشده در این بسته قرار نگرفته‌اند. تا زمان افزودن Wrapper استاندارد، workflow از Gradle 8.9 نصب‌شده در GitHub Actions استفاده می‌کند.
